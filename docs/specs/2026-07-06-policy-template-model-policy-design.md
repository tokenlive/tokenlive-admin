# 策略模板与模型策略实例重构设计

本文档记录 `tokenlive-admin` 中治理策略的数据权限与交互重构方案。目标是在保留策略复用便利性的同时，让运行时生效策略的数据权限收敛到已有的模型权限体系。

## 背景

当前策略与策略绑定是独立资源，容易出现权限不一致：

- 用户有某个模型权限，但没有被绑定策略的权限，查看模型绑定列表时需要脱敏或额外授权。
- 策略可被多人复用后，策略修改、绑定修改、生效范围的责任边界不清晰。
- 如果把策略本体和绑定关系都做独立数据权限，后端授权、前端展示和异常态处理都会明显复杂化。

因此本次重构采用“策略模板 + 模型策略实例”的设计：模板只负责复用配置，模型策略实例才是运行时可生效资产。

## 核心概念

### 策略模板

策略模板是 `model_id` 为空的策略记录。

- 只作为复用配置，不参与运行时生效。
- 不创建策略绑定，不同步到 Redis。
- 由平台管理员维护，普通模型管理员默认不可创建或修改模板。
- 在策略模板详情页可以选择模型并复制生成模型策略实例。
- 模板修改不级联影响已复制出的模型策略实例。

### 模型策略实例

模型策略实例是 `model_id` 非空的策略记录。

- 归属于一个具体模型，权限完全跟随该模型的数据权限。
- 可在模型详情页中创建、编辑、删除、启停。
- 可由模板复制生成，也可在模型详情页直接新建。
- 才允许创建策略绑定并同步到网关运行时配置。
- 同一模型下策略名称唯一，不要求全局唯一。

### 策略绑定

策略绑定是模型策略实例的运行时作用范围。

- 不再作为独立用户资产做数据权限管理。
- 只能绑定 `model_id` 非空的模型策略实例。
- 不保留独立 `enabled` 字段，启停状态以策略本体为准。
- 绑定中的 `model_code` 是运行时匹配维度，必须与策略实例所属模型保持一致。

## 数据模型

各类策略表保留 `model_id` 字段，但允许为空：

- `model_id IS NULL`：策略模板。
- `model_id IS NOT NULL`：模型策略实例。

约束建议：

- 模型策略实例名称在同一 `model_id` 下唯一。
- 策略模板名称在模板集合内唯一。
- 绑定表不再保存 `enabled`。
- 绑定表通过 `policy_id` 指向具体策略实例，不能指向模板。

因为当前不考虑线上数据迁移，本设计可直接调整初始化 SQL 与开发环境数据结构。

## 权限规则

### 模板权限

- 模板列表、创建、编辑、删除走平台级能力或 RBAC 菜单/API 权限。
- 模板不跟随模型数据权限。
- 模板不能被直接绑定到租户、用户或模型运行时维度。

### 模型策略实例权限

- 读模型策略：需要拥有所属模型的读权限。
- 创建模型策略：需要拥有目标模型的写权限。
- 编辑、删除、启停模型策略：需要拥有所属模型的写权限。
- 复制模板到模型：需要模板可读权限，以及目标模型写权限。

### 绑定权限

- 查询绑定列表时，以策略实例所属模型权限为准。
- 创建、更新、删除绑定时，以策略实例所属模型写权限为准。
- 因为模板不可绑定，不再出现“有模型权限但无策略权限”的展示冲突。

## 交互设计

### 策略管理页

现有策略列表页调整为策略模板管理页：

- 默认只展示 `model_id IS NULL` 的模板。
- 支持模板新增、编辑、删除、详情查看。
- 模板详情页提供“复制到模型”动作。
- 复制时选择目标模型，后端创建新的模型策略实例。
- 如果目标模型下名称冲突，后端自动追加后缀，例如 `策略名-2`。

### 模型详情页

不新增独立的模型策略页，在模型详情页增加治理策略 Tab：

- 每个策略类型一个 Tab，例如限流、路由、熔断、调用管理、负载均衡、染色打标。
- 每个 Tab 展示当前模型下该类型策略实例。
- 支持新建模型策略实例。
- 支持从模板复制。
- 支持编辑、删除、启停和查看绑定范围。
- 一期优先复用现有表格与弹窗组件，减少前端重写范围。

## 后端接口设计

建议接口能力分为两类：

- 模板接口：查询、创建、更新、删除 `model_id` 为空的策略。
- 模型策略接口：按 `model_id` 查询、创建、更新、删除、启停策略实例。

复制模板接口建议：

```text
POST /api/policy/{type}/{template_id}/copy-to-model
```

请求参数：

```json
{
  "model_id": "target-model-id",
  "name": "optional-new-name"
}
```

后端行为：

- 校验源策略是模板。
- 校验当前用户可读模板。
- 校验当前用户可写目标模型。
- 复制策略字段，生成新的策略 ID，写入目标 `model_id`。
- 为模型策略实例创建或刷新对应绑定关系。

## 实施顺序

1. 调整领域文档和 ADR，统一术语。
2. 修改策略表结构：`model_id` 允许为空，绑定移除 `enabled`。
3. 后端区分模板查询与模型策略查询。
4. 后端增加模板复制到模型的能力。
5. 后端限制模板不可绑定、不可同步 Redis。
6. 前端将策略管理页调整为模板管理。
7. 前端在模型详情页增加治理策略 Tabs。
8. 补齐策略实例创建、删除、绑定清理的测试。

## 验证计划

- `go test ./internal/mods/policy/... ./internal/mods/resource/...`
- `go build ./...`
- 前端修改后运行 `npx prettier --config .prettierrc --write <changed-files>`
- 前端构建验证 `npm run build:test`
- 手动验证：
  - 模板列表不展示模型策略实例。
  - 模板不能直接绑定。
  - 从模板复制到模型后生成新策略 ID。
  - 模型详情页只展示当前模型策略实例。
  - 无目标模型权限的用户不能复制模板到该模型。

# 模型指标观测

状态：已实现并验证。

## 范围

第四部分将模型排行与模型详情卡片的裸数值改为逐项指标观测，沿用既有 Request 口径。供应商上游调用仍使用独立计数，不混入模型请求。首页 ClickHouse 四类趋势继续独立，不改变未启用时隐藏整卡的规则。本轮不改模型 TTFT／OTPS 时间序列读取协议和首页 Overview 卡片协议。

## 决定

- `ModelRankingItem.requests` 原子返回同源、同窗口的总请求、成功与失败计数；成功率仅从该计数派生。零分母没有成功率。
- 所有指标使用 `MetricObservation` 返回可空值、状态、来源、统计范围、窗口、覆盖及稳定原因。原 Provider `HealthMetric` 泛化为同一观测类型，供应商 JSON 字段保持不变。
- 真实 0 正常显示，无样本、未支持和读取失败分别表示。模型精确查询保留零请求行；停用模型的筛选范围保持既有行为。未知值始终排在有效值后面，前端升／降序都遵守。
- Prometheus 请求计数通过同一次按 model/status 分组的查询读取 success/error，保持现有状态筛选。已有有效模型结果分组但另一结果未出现时，另一计数为零；已出现的无效样本不被填零。性能各项独立查询、保留独立错误和有效性，某项失败不清空整个模型排行。
- Redis 计数按真实两小时保留区间读取；键存在且为零与完全无键分开。历史窗口过期或读取失败时使用可覆盖的本实例内存，明确部分数据。
- 非 Prometheus 路径的请求计数和性能独立取源。Redis 仅有请求计数；无内存性能样本时，不能把 Redis 不支持的性能显示为零。Memory 有请求但缺首包样本时是无样本，不是能力不支持。Memory 不保存直方图，分位数明确未支持。
- 公共观测展示集中来源、原因与格式化，模型和供应商共享。缓存克隆观测指针，不缓存错误结果，避免一次失败阻止恢复。

## Interface

继续以 `Reader.Read` 为后端 seam，以 `MetricObservation` 为指标返回 interface。模型与供应商是两种真实调用方，各源 adapter 共用有效性读取，集中这些规则以增加 module 的 depth、leverage 与 locality。HTTP、WebSocket、首页表格与详情卡片同步迁移，不保留旧裸数值响应。

## 验证

- 19 项模型观测合同测试经公共 Read 验证零值／缺失、单项失败、请求与上游尝试分离、历史覆盖、排序、缓存隔离、来源能力及原停用筛选行为。Dashboard 与 MemoryStore 全部测试及竞态检查通过。
- 前端 137 项测试通过，模型首页真实 Ant 表格升／降序、模型与供应商详情、供应商卡片和首页快照浏览器回归通过。前后端生产构建通过，Swagger 已重新生成。
- 删除已无消费者的旧 Prometheus map 读取及其无效样本归零逻辑；公共展示不保留供应商专用兼容别名。
- 同步既有 API Key 卡片隐藏行为的旧视图测试，未改动其产品行为。

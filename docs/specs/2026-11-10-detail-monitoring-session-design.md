# 详情监控查询会话

状态：已实现并验证。

## 范围与约定

第三部分整理模型／供应商详情的监控读取，继承现有指标含义和有效性规则。前两部分的 Reader、MetricObservation 与 ClickHouse 使用趋势不另建兼容协议。

- 一个详情监控会话拥有资源身份、选定的绝对起止及事件分页。刷新或更换筛选建立新一轮；事件翻页沿用已选窗口，只查询事件；手动刷新重置到第一页。
- 资源变化、失活和卸载使已有请求失去写入资格。旧响应不能写入新资源或新筛选，旧事件页不能覆盖新页。
- 模型的排行、请求趋势和性能用同一 Snapshot 查询；供应商的健康和上游趋势用同一 Snapshot 查询。现有 Snapshot 只有一个 traffic 槽，端点趋势继续独立读取，不扩展后端通用批量协议。
- 供应商端点按模型去重读取，过滤自身端点，并按绝对窗口／桶校验合并。某项失败保留其他可用项并说明部分覆盖；全部失败与真实空数组分开。
- 目录、熔断和事件也保留读取状态。模型目录读取全部分页，继续包含停用端点；供应商顶部启用比例仍表示启用数／总数，不能将熔断读取失败当作全部正常。

## Module 与 interface

`createDetailMonitoring` 是两种详情监控的共同 seam。视图仅提交资源和窗口、请求刷新或事件翻页并消费状态。其 implementation 隐藏 Snapshot 选择、transport adapter 调用、异步身份、端点 fan-out 和局部错误；这些行为由同一 interface 的测试覆盖，增加 depth、leverage 与 locality。

供应商父页保留当前目录／近一小时健康摘要的独立读取，并加上路由和请求身份保护。摘要与可筛选监控窗口含义不同，本轮不引入跨视图长缓存。

## 验证

前端 133 项测试通过，包含会话的可控异步测试；覆盖请求合并、固定窗口翻页、资源与事件页竞态、失活、请求复用、完整目录分页、端点结果对齐、无样本与错误区分。真实模型／供应商 Tab 和供应商父页浏览器检查通过，供应商指标卡片回归通过；生产构建通过。

不再使用的单项趋势／模型排行／模型性能读取包装已删除。后端熔断读取同时改为传播运行时／目录读取错误，HTTP 返回稳定 503，不泄漏源错误；成功响应仍为原数组。Overview 将未知熔断列表保留为 null 并标记部分数据，不能用空数组冒充健康。Snapshot 协议及第一、二部分的源口径保持有效。

补充验证：熔断器的真实空列表、运行时失败、目录失败和缺失目录元数据均有 Reader／HTTP 合同测试；Dashboard 与 MemoryStore 测试及竞态检测通过。

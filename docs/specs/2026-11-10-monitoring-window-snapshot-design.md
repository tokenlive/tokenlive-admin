# 旧监控窗口与快照 module 设计

状态：已确认并实现。决策记录见 [ADR-0011](../adr/0011-monitoring-snapshot-window-plan.md)。

## 目标与范围

用户在架构报告中选择候选①，深化旧监控的窗口与快照 module：集中时间解析、截点、分桶、来源可覆盖窗口与缓存时间身份，减少 HTTP／WS adapter 和图表调用方需要理解的隐含约定。

主要涉及旧流量趋势、模型性能趋势、模型排行及首页 WS 快照；供应商查询只讨论真正相同的窗口机制。供应商健康结果语义与详情页多查询组合是另外两个候选，不在本次自动扩展范围内。

## 已确认决定

2026-11-10，用户确认：

1. 在功能含义不变的前提下，为优化结构可以不兼容原有 interface，包括原有查询入口和返回结构；无需以旧 URL、参数或 JSON 字段形状限制新设计。迁移时同步更新仓库内调用方。
2. 同一监控快照共用一次捕获的评估截点，各指标仍保留自身统计窗口。趋势、性能、排行使用同一截点，顶部“今日累计”“实时 QPS”“近 5 分钟延迟”保持各自含义。
3. 旧监控使用明确的查询时区，缺省使用服务端时区。历史查询的 `today` 取该时区下所选日期的零点至所选截点；日界时区参与缓存身份。
4. 窗口截止到完整分钟，保留最后一个未完整大桶并标明真实起止时间。例如评估截点为 `10:37:42`，实际统计到 `10:37:00`，五分钟分桶的末桶为 `10:35–10:37`。
5. 历史数据覆盖不足时保留可用部分，明确表达不完整及实际覆盖范围；缺失时段不伪装为零，完全无法覆盖时返回不可用。
6. 以 `monitor.Reader.Read(ctx, Query)` 为外部 interface，内部采用私有不可变窗口计划；HTTP／WS 共用同一快照返回类型。
7. 非法格式、时区及未来截点返回错误；省略参数使用明确缺省值。
8. 某项读取失败不丢弃其他成功项；输入无效则整次请求拒绝。

“功能含义不变”不要求保留已发现的时间解释缺陷：七天范围不应退化为一小时，历史截点不应被模块内部重新读取的当前时间取代。

## 保留的领域约束

- Request 与 Upstream Call 的计数、成功率分母保持独立。
- ADR-0008／0009 中的供应商上游健康视角、范围限制和 Provider code／name 兼容继续有效。
- ADR-0010 中的新 ClickHouse 使用趋势保持独立统计语义：半开日志窗口、取消请求计失败、异步落库、未启用隐藏整卡、查询失败重试。
- 监控快照表示共同评估时刻，不承诺不同数据源的原子一致性或不同统计窗口的数值相等。

## 已核实的架构摩擦

- `resolveTrendRange`、`resolveTimeRange`、`memoryRangeMinutes` 与供应商窗口函数分别解释相同时间范围。
- 模型排行的 `today` 解析重新读取 `time.Now()`，未使用调用方传入的历史截点。
- 内存模型排行直接使用不支持 `d` 的 `time.ParseDuration`，使 `7d` 回退为默认一小时。
- 单次 WS 推送分别调用各自读取当前时间的查询，跨分钟或午夜时可能拥有不同截点。
- 缓存身份包含截点的 Unix 秒，但未包含影响自然日与展示标签的时区信息。
- 旧趋势对 `today` 舍弃末个未完整大桶，其他部分路径纳入当前分钟；详情自定义窗口通过时长取整重建起点，可能扩大左侧范围。
- Redis 分钟数据从写入起保留两小时，内存分钟明细相对当前时间保留七天；历史短窗口也可能已经过期，不能仅按窗口长度推断覆盖能力。

## Interface 候选比较

已分别按最小 interface、可复用窗口计划、常见调用流程三种约束完成独立设计。

| 候选 | External seam | Depth 与 locality 的取舍 |
| --- | --- | --- |
| 单次快照读取 | 读取指定的旧监控结果 | 调用方不接触来源、分桶和缓存；内部承担多个具名结果的协调 |
| 不可变窗口计划 | 将查询意图编译为窗口计划 | 纯时间规则可直接复用，但调用方仍需组织读取、降级及快照组合 |
| 面向首页和详情的读取流程 | 直接读取指定页面需要的旧监控结果 | 常见调用简单，但入口更宽，容易将本次范围扩成详情编排重构 |

最终选择：单次快照读取作为 external interface，不可变窗口计划作为 module 的私有 implementation。查询选择限定为现有旧监控用途，返回各自具名的领域结果与实际窗口、覆盖状态，不引入通用指标表达式或图表引擎。HTTP／WS adapter 共用读取流程，窗口和来源 adapter 不再自行读取当前时间。

窗口规划属于 in-process；现有 Prometheus、Redis、内存 adapter 以及本地 HTTP fixture、临时 Redis、内存 store 可用于穿过实际 seam 验证。测试应围绕调用方使用的 interface 验证行为，不仅验证内部 helper 的形状。

## 已实现的 interface

`POST /api/v1/dashboard/snapshot` 示例：

```json
{
  "timezone": "Asia/Taipei",
  "overview": true,
  "traffic": {"range": "6h", "group_by": "model"},
  "models": {"range": "today", "sort": "request_count", "limit": 10}
}
```

历史／自定义查询使用 RFC3339 `at` 与各结果中的 `start`；省略 `at` 使用同一次捕获的当前时间。只返回所选 Reading，每项包含 `state`、`source`、`window`、`buckets`、`coverage`、`data` 或稳定错误码。序列位置与返回桶一一对应，前端不能按标签反推范围。

Overview 为实时读取；`windows` 说明日累计、QPS 与延迟的各自窗口。日累计依赖本地自然日聚合，午夜不等于采集时区午夜时返回 null。延迟／TTFT 没有有效样本时保持 null。Redis／内存保留边界穿过的桶保守置 null，不把局部桶当成完整值。

## 实现与验证

- `internal/mods/dashboard/monitor` 集中窗口、覆盖范围、缓存和源查询，按职责拆分文件；HTTP／WS 不再实现指标计算。
- 首页初次 HTTP 与后续 WS 使用同一快照结构；模型、供应商详情使用同一转换 adapter，筛选更新丢弃旧响应。
- `monitor/reader_test.go` 通过实际 Read seam 覆盖共同截点、七天、历史时区、保留范围、缓存隔离、最后部分桶、无效输入、取消和局部失败；HTTP／WS 测试覆盖统一契约。
- 前端转换与成功率测试覆盖 null、零分母和状态优先级；浏览器验证未启用 ClickHouse 隐藏整卡，以及旧监控部分失败与快速切换筛选。

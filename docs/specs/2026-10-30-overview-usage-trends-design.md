# 首页综合趋势图设计

状态：产品设计已确认。2026-10-30 开始讨论，2026-11-09 确认完全部 13 项决定。

## 目标

参考用户提供的网关趋势图，在首页总览新增“横向分类按钮、当前分类汇总、时间趋势曲线”组成的综合趋势卡片，便于快速查看请求、Token 用量、延迟和错误。

## 位置与交互

- 在顶部六张指标卡下方新增独占一行的趋势卡片，保留现有流量走势与今日 Token 分布。
- 右上方以横向按钮提供“请求、用量、延迟、错误”四个分类，默认打开“请求”。
- 首期展示全平台汇总；按模型、供应商查看继续使用已有图表。
- 默认时间范围为“今日”，支持近 1 小时、6 小时、24 小时、7 天。四个分类共用卡片的时间选择，切换分类保持时间范围。
- 分类下方展示当前分类的时段汇总，再展示趋势曲线。汇总数字对应所选时间范围，不固定展示今日累计。
- 四个分类使用一致的时间窗口与数据快照，避免切换分类时比较不同批次的数据。

## 分类指标

| 分类 | 趋势曲线 | 顶部汇总 | 单位与坐标 |
| --- | --- | --- | --- |
| 请求 | 总请求、成功、失败 | 时段总请求数、成功数、失败数 | 次，各曲线共用数量轴 |
| 用量 | 输入、输出、缓存命中、缓存写入 | 时段输入、输出、缓存命中、缓存写入 Token 数 | Token |
| 延迟 | 平均响应耗时、平均首 Token 延迟（TTFT） | 时段平均响应耗时、平均 TTFT | 毫秒 |
| 错误 | 失败数、失败率 | 时段失败数、失败率 | 失败数用数量轴，失败率用百分比轴 |

### 请求与错误

- 以用户请求的最终结果计数，不以故障转移产生的上游调用次数计数。
- 成功判断沿用现有 ClickHouse API Key 用量排行的状态码口径：`200 <= status_code < 400`；其他已记录请求计入最终失败。
- 客户端主动取消（当前日志为 `499`）计入总请求和最终失败。最终失败表示请求未成功完成，不一定表示网关故障。
- 每个时间桶满足：总请求数 = 成功数 + 失败数。
- 桶内失败率 = 桶内失败数 / 桶内总请求数；时段失败率 = 时段失败数 / 时段总请求数。整体失败率不通过平均桶内失败率计算。
- 请求数为零时，数量为 `0`，失败率为缺失值并在界面显示“—”。

### Token 用量

- 四类 Token 分别按请求日志中的输入、输出、缓存命中和缓存写入字段汇总。
- 输入包含缓存命中和缓存写入 Token；总 Token = 输入 + 输出，不再累加缓存。四条曲线不能堆叠成总 Token。
- 桶内曲线展示该桶用量，顶部展示整个时段的对应累计值。

### 延迟

- 平均响应耗时纳入全部已记录请求，包括成功、失败和取消；日志中的 `0ms` 可能是真实的不足 1ms，仍计入样本。
- TTFT 只纳入 `is_stream = 1` 且 `ttft_ms > 0` 的有效样本，不额外限制最终请求结果。非流式请求和没有有效首 Token 数据的请求不进入 TTFT 分母。
- 桶内均值和时段均值均按各自样本的耗时总和 / 样本数计算；不直接平均时间桶均值。
- 没有有效样本时返回缺失值，汇总显示“—”，曲线不绘制为 `0ms`。
- 首期展示两个平均值，不扩展 P95/P99 或 OTPS。

## 时间窗口与刷新

- 查询窗口为 `[start, end)`，按日志中的请求开始时间归桶。请求完成并落库后才进入统计，晚到日志补回开始时间所在桶。
- “今日”沿用 Admin 服务端时区的自然日边界，并在界面标明时区。近 1 小时等滚动窗口使用同一结束时间。
- 分桶沿用现有趋势粒度：近 1 小时 1 分钟、近 6 小时 5 分钟、近 24 小时 15 分钟、近 7 天 2 小时；今日动态选择 1、5、10 或 15 分钟，使点数不超过 120。
- 首尾时间桶必须裁剪到所选窗口；桶之间不重复、不遗漏请求，汇总与曲线覆盖同一请求集合。
- 首页可见且处于激活状态时每 30 秒刷新；切换时间范围立即查询。页面隐藏或离开首页时暂停刷新，恢复可见时刷新当前窗口。
- 图表和汇总更新为同一批次的数据；筛选切换后不将旧窗口的结果显示为新窗口的数据。

## 数据来源与状态

- 四个分类及其顶部汇总统一查询 ClickHouse 已落库请求日志，接受异步写入和补偿导致的最新时段短暂延迟；不自动降级到 Prometheus 或 Redis 的另一套统计。
- 使用去重后的请求日志，沿用现有明细读取中的 `FINAL` 语义，避免补偿重写的重复记录扩大计数和用量。
- 当前请求日志已包含四类 Token、响应耗时和流式首 Token 延迟；需要新增分桶聚合查询，不能从已有今日累计值反推时序，也不能直接复用已按 API Key 聚合后丢失时间维度的榜单结果。
- 数据读取失败与空结果必须在后端和界面上区分。查询失败不可作为成功的零值结果缓存。

| 状态 | 界面行为 |
| --- | --- |
| 查询成功，存在请求 | 展示当前窗口的汇总和曲线 |
| 查询成功，没有请求 | 数量显示 `0`；响应耗时、TTFT 和失败率显示“—” |
| ClickHouse 未启用 | 隐藏整张使用趋势卡片，不显示标题、控件、提示或空白占位 |
| 查询失败 | 显示错误和重试入口，不将失败解释为没有请求 |

## 权限与兼容

- 沿用首页总览的访问权限，前后端均按现有登录与权限规则控制；新图不额外要求 Root。
- 新查询只返回全局汇总及分桶结果，不返回租户、用户、API Key、请求明细或凭证信息。
- 不改变现有 API Key 明细排行的 Root 专属权限。
- 现有流量图使用监控统计，当前不计入客户端取消；新图使用已落库请求统计并包含取消。因此新旧图及顶部实时指标不承诺逐项相等。
- 涉及的前端文件修改后须按项目要求使用 Prettier 格式化，并沿用现有主题和中英文文案机制。

## 验收场景

1. 首页在六张指标卡下新增整行卡片，默认“请求 / 今日”，横向四个分类均可切换；旧图仍可使用。
2. 切换分类保留时间范围；切换时间后，曲线和汇总同时对应新窗口，慢返回的旧请求不会覆盖它。
3. 一次请求调用 A 失败、故障转移到 B 成功，计为 1 次请求、1 次成功、0 次最终失败。
4. 一次客户端取消计为 1 次请求、0 次成功、1 次最终失败；失败数在请求和错误分类中相同。
5. 输入为 100、输出为 20、缓存命中为 60、缓存写入为 10 时，总 Token 为 120；缓存分别展示，不重复累加。
6. 两桶响应耗时分别为 1 个样本、100ms 和 9 个样本、各 10ms 时，时段平均为 19ms，不是 55ms；真实 `0ms` 样本仍进入分母。
7. 有请求但没有有效流式首 Token 样本时，请求和响应耗时正常显示，TTFT 显示“—”；没有请求的桶，失败率同样显示“—”。
8. 时区、跨午夜、窗口首尾和晚到日志保持归桶一致；去重后的分桶数量相加等于同一窗口汇总数量。
9. 未启用数据源时整张使用趋势卡片不渲染，其他总览内容正常显示；查询失败和成功无请求分别呈现对应状态，重试可恢复，失败不会生成一条零值曲线。
10. 页面激活时按 30 秒周期刷新，隐藏或离开时暂停；有总览权限的非 Root 用户能查看汇总，越权请求被后端拒绝，结果中不包含身份或凭证明细。

## 实现记录

2026-11-10 按用户更新的展示要求，ClickHouse 未启用时隐藏整张使用趋势卡片，移除原有未启用提示；查询失败的错误与重试入口继续保留。

2026-11-09 接入首页与后端，新增 `GET /api/v1/dashboard/usage-trends?time_range=today`。接口沿用总览菜单授权，返回 `state`、`data_source`、`window`、`generated_at`、`bucket_seconds`、`summary` 和 `buckets`；四个分类共用一份响应，切换分类不重复查询。

- `schema/usage_trends.go` 定义窗口、分桶、可空指标及对外结构。
- `dal/usage_trends.go` 对 `access_logs FINAL` 按窗口起点分桶，显式绑定毫秒时间戳，避免驱动默认按秒绑定导致窗口边界丢数。
- `biz/usage_trends.go` 在同一请求集合上计算分桶与加权汇总，提供 30 秒缓存及并发请求合并；失败不缓存，“今日”缓存不跨自然日。
- `api/usage_trends.api.go` 校验登录和参数，数据源错误返回不含连接细节的 503。总览菜单中增加新接口资源，Root 排行权限保持独立。
- 前端 `UsageTrends.vue`、`useUsageTrends.js` 与 `usage-trends-state.js` 实现四分类卡片、激活与可见性控制、取消旧请求及忽略过期响应。支持中英文、明暗主题和窄屏布局。

验证覆盖统计口径、加权均值、空样本、跨午夜缓存、毫秒窗口、菜单授权及普通用户访问。前端 112 项测试、卡片与完整首页的浏览器检查、后端 Dashboard 模块 race 检查、应用包构建和前端生产构建通过。

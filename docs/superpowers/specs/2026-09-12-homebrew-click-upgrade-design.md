# Homebrew 单机版点击升级

状态：产品边界已逐项确认；本文为整体设计审阅稿，尚未实施。下述工程默认值和实现验证门槛随本文一起审阅，不能视为已经验证的运行能力。

## 1. 目标与已确认决策

在现有版本提醒基础上，支持获授权用户点击升级 Homebrew 单机版，不再必须手工执行升级命令。

已确认：

1. 满足运行条件时默认允许点击升级，不新增本机开关，也不要求维护者额外开启。
2. 发现新版只提示；必须由用户发起，并二次确认目标版本和服务重启影响。
3. 安装后自动重启，明确告知正在处理的请求可能中断，不承诺零停机。
4. 新增独立的“单机版升级执行”权限，Root 默认拥有，其他角色单独授权；现有“版本更新管理”不自动包含安装权限。
5. 首期仅支持 Homebrew 安装、由 `brew services` 托管、运行用户具备安装和重启权限的环境；不使用 sudo 自动提权。
6. 采用与主服务生命周期分离、同一系统用户运行的一次性升级任务；关闭网页不取消任务。
7. 同一安装同时只有一个升级任务；状态和诊断记录持久化，服务重启后可继续查询。
8. 用户确认哪个目标版本，只允许安装该目标；目标变化或无法保证一致时停止并要求重新确认。
9. 预检/下载失败不主动停止当前服务；安装/重启失败保留诊断和人工恢复指引，不循环重试，不承诺自动降级或数据库回滚。
10. 只有确认目标版本正常运行才显示成功。

本设计是新能力，不修改此前仅查看/检查/复制指令的既有含义。专业版不获得本机升级执行能力；非支持安装保留提醒与手动指引。

## 2. 方案选择与职责

| 方案 | 取舍 |
| --- | --- |
| 独立的一次性升级任务（已选） | 可以跨主服务重启完成核验；需要可靠的系统任务托管和持久状态 |
| 主服务进程内执行 | 生命周期与被升级服务耦合，重启期间难以继续负责核验和结果记录 |
| 常驻升级服务 | 生命周期清晰，但新增长期安装、权限和维护负担，首期不采用 |

- Admin：提供鉴权、角色资源、确认窗口、任务状态及安全的结果展示。
- Standalone：识别实际安装、验证执行条件、管理任务、调用固定升级操作、请求服务重启并核验。
- Homebrew 适配层：处理经过验证的 Formula/安装元数据及受支持的安装接口；不由浏览器选择命令。
- 系统任务托管层：独立于主服务启动一次性执行器；不自动反复启动失败任务。

通过 Admin 的可选宿主能力接口连接 Standalone，未提供能力的独立 Admin 正常启动并返回“不支持”，不得反向引入对 Standalone 模块的依赖。不改 Gateway 转发流程。

## 3. 运行条件与权限

### 3.1 运行条件

后端综合判断，不只依赖前端隐藏按钮或 Homebrew 安装标记：

- 实际可执行文件、安装记录、受控 TokenLive Formula 和 Homebrew 前缀对应同一安装。
- 当前进程由该安装的 `brew services` 服务托管，服务身份和管理域可验证；“机器上存在同名服务”不能证明当前进程符合条件。
- 执行器与当前服务使用同一非 root 系统用户，具备正常升级所需的目录权限和对应服务管理权限。
- 受支持的系统任务托管和精确目标安装能力已通过实现验证。
- 无活动升级任务、未决安装状态或需要人工处理的包管理冲突。

当前仓库 Homebrew Formula 声明的是 macOS Intel/Apple Silicon 产物。首个实现适配以这些实际发行产物为对象；不能因为 Linux 也存在 Homebrew 就宣称支持 Linux 点击升级。其他安装方式维持手动路径，不自动迁移服务管理器。

无法验证条件时显示具体原因及手动指引，不自动修复权限、解除 pin、切换服务用户、修改 tap 信任或重写用户的安装布局。无需本机开关；“当前环境不支持”是能力检查，不是隐式开关。

### 3.2 权限

- 升级执行权限由后端现有 Root/角色授权体系检查，不能根据用户名判定。
- 仅有版本查看/检查权限不能准备或创建升级任务。
- 执行权限允许读取本次确认所必需的目标信息与升级任务结果，不反向授予其他管理权限；页面须适配只获得执行权限的角色。
- 当前版本仍对普通登录用户可见；升级记录、发起人、日志和安装详情不加入公开版本接口。
- 预览、提交、结果读取分别鉴权。提交时重新校验权限，权限已撤销则拒绝。
- 已接受执行的任务不因关闭页面、退出登录或权限随后撤销而强制终止安装；撤权用户不能继续读取受限结果或发起新任务。
- 保留现有关闭联网检查的语义：关闭检查时不允许新建需要外网校验/下载的升级任务，不引入另一个开关；已进入安装阶段的任务不得靠配置变化强制中断。

## 4. 用户流程与目标一致性

1. “关于”展示可升级结果、运行条件和按钮；读取状态不自动执行 Homebrew 更新命令。
2. 用户点击“立即更新”后进行准备校验，页面展示当前版本、准确目标版本、受控发行说明、自动重启警告和备份提醒。
3. 服务端生成有时效、绑定用户与安装的确认凭据。前端只提交该凭据及确认动作，不提交任意 URL、文件路径、版本字符串或命令作为执行依据。
4. 二次确认时重新检查权限、凭据、安装状态与候选身份。目标或安装状态变化时使确认失效，要求刷新后再次确认，不静默选择另一个版本。
5. 接受任务后返回任务 ID，持续展示阶段进度。刷新或关闭页面不会重复创建任务。
6. 服务重启期间显示“正在重启/等待恢复”，不能将暂时断连当成成功或立即失败。恢复登录后查询原任务。
7. 只有执行器完成本机核验后才记录成功；前端根据持久任务结果显示最终结论。

目标描述包含稳定版本、受控 tap/Formula 身份、Formula 修订或内容指纹、平台/架构、产物校验信息；仅相同版本字符串不足以表示相同目标。

安装必须消费已经确认并固定的目标描述。仅在 `brew upgrade` 前比较一次版本、或仅设置 `HOMEBREW_NO_AUTO_UPDATE`，不能当成精确目标保障。不得直接覆盖 Cellar/opt 文件或自造安装收据绕过 Homebrew 管理。

若受支持的 Homebrew 接口无法保证安装输入固定，则该适配不得开放点击升级，应如实返回无法保证目标一致并保留手动路径。具体可行机制是第 9 节的前置技术验证，而不是本文声称已经实现的能力。

## 5. 一次性任务与持久状态

任务由系统以独立身份托管，不能只在主服务内创建 goroutine 或假设普通子进程必然跨重启存活。macOS 可行方向为独立的用户级 launchd job，服务标签与 TokenLive 主服务分离；具体注册/清理机制必须先验证。

执行器和状态文件位于不会随旧版包被替换而消失的受控目录。执行器来自当前已安装、可信的程序或其配套组件，不下载远端脚本执行。只有启动升级时才创建一次性任务，不安装常驻守护进程，不跨系统用户提权。

拟定状态：

| 状态 | 含义 |
| --- | --- |
| preparing | 校验运行条件、更新候选和确认凭据 |
| awaiting_confirmation | 等待用户确认，尚未开始安装 |
| queued / downloading | 任务已接受，准备并校验固定目标产物 |
| installing | Homebrew 正在安装；不能通过取消网页强制打断 |
| restarting | 对已确认的 TokenLive 服务执行重启 |
| verifying | 等待本机服务恢复，核验目标版本与身份 |
| succeeded | 核验通过 |
| failed | 已知失败且执行过程已结束，记录失败阶段 |
| needs_attention | 进程/安装状态无法确定，需要人工检查，不盲目重试 |
| confirmation_expired | 确认过期或目标变化；没有进入安装 |

状态原子落盘；记录任务 ID、安装身份、发起人、当前/目标版本、目标指纹、阶段、时间、有限错误类别和安全摘要。只记录必要诊断，不持久化登录 token、同步密钥或完整业务配置。数据目录仅执行用户可访问，拒绝越界路径和不可信符号链接。

安装级互斥锁覆盖执行器完整生命周期，确认凭据和幂等请求防止双击、并发用户和请求重放。任务记录本身不能代替实际进程锁；主服务重启不得误认为任务已结束并再开一个任务。

不承诺阻止同一系统用户在终端手工操作 Homebrew。检测到外部包管理冲突或安装身份变化时暂停自动推进，保留诊断；不能用删除他人的锁文件来强行继续。

## 6. 执行安全、失败和恢复

- 只执行经过审核的 TokenLive 升级及服务管理操作；使用固定命令和独立参数，不拼接 shell 字符串或执行候选返回的命令。
- 使用受控环境和已验证的可执行文件路径，不继承会改变源、路径或命令行为的不相关变量。
- 禁止裸 `brew upgrade`、全局清理、自动卸载其他包和自动解除版本 pin；对 Homebrew 可能带来的依赖、清理和其他副作用做显式审查，无法满足本次边界时停止。
- 预检/下载阶段不主动停止当前服务；安装/链接过程中不能保证原进程和全部资源完全不受影响，确认窗口不宣称只有最终重启才有风险。
- 安装成功后仅重启已识别的同一 TokenLive 服务，不使用泛化进程匹配或停止其他服务。
- 核验包括：服务进程属于预期安装、运行版本等于目标、必要初始化完成并健康响应。不能只检查 HTTP 200、端口开放或网页重连。
- 主服务无法恢复时，网页明确显示尚未恢复；本地任务状态和日志必须能通过 CLI 读取，不能把 Web API 当成唯一诊断途径。
- 网络/权限/锁/校验失败均记录阶段，显示可操作的手动指引。安装失败后不自动降级，不自动还原数据库，不重复执行不确定的安装。
- 首期不提供“安装中取消”，不承诺断电后自动续装。确认之前可退出；执行器异常退出后恢复状态应为 needs_attention，直到确认没有未决执行才能允许重新发起。
- 不新增自动业务数据备份/还原系统；确认时提醒维护者确认已备份，已有配置保留规则继续生效，不能承诺跨版本数据库兼容。

以下为供本次整体审阅的工程默认值，不是已经运行验证的参数：

| 参数 | 拟定默认值 |
| --- | --- |
| 确认凭据有效期 | 5 分钟；一次使用，绑定用户/安装/目标 |
| 准备检查上限 | 2 分钟 |
| 下载阶段上限 | 10 分钟 |
| 安装阶段上限 | 10 分钟 |
| 重启及健康核验上限 | 合计 3 分钟 |
| 已接受任务总时限 | 30 分钟 |
| 页面状态轮询 | 可见时每 2 秒；重启等待退避至最多每 10 秒 |
| 终态记录保留 | 最近 20 条；单任务日志最多 5 MiB，截断有标识 |

超时不表示系统已恢复或外部命令已结束。若不能安全确认子进程退出，标记 needs_attention 并阻止新任务；不强制删除 Homebrew 锁或靠杀进程制造成功。活动任务、未决任务和人工恢复需要的记录不自动清理。

## 7. 接口与页面边界

接口职责在实施计划中映射为仓库标准路由，不在本文预先固定函数签名：

- 能力读取：返回是否支持、允许执行与否、阻止原因、当前活动任务；只做只读识别或读缓存。
- 升级准备：鉴权后校验候选、安装身份和环境，生成短期确认凭据；不安装或重启。
- 提交任务：再次鉴权并验证凭据，以幂等语义接受唯一任务，返回可查询 ID。
- 任务读取：受执行权限保护，返回持久阶段、安全结果和有界诊断。
- 本地诊断：服务不可用时仍能读取同一份任务状态，不需要借用登录 token。

所有写入口使用现有认证并增加与浏览器会话相匹配的跨站请求防护；不能只依赖 CORS 或按钮禁用。错误响应明确区分无权限、不支持、目标变化、确认过期、任务冲突和检查关闭。

页面保留原有更新状态；“执行升级”能力与“检查版本”能力分别判断。不支持自动升级时给原因与原手动命令，不显示误导的安装成功或确定进度百分比。展示阶段而非伪造下载/安装百分比。

## 8. 测试与验收

1. 默认符合条件就能发起，不存在本机启用开关；发现新版不会自动执行。
2. Root、执行授权角色、仅检查授权角色、普通用户、权限撤销均覆盖后端与前端。
3. Homebrew 标记存在但并非对应服务、root/权限不足、非支持安装均不能执行。
4. 双击、并发用户、过期凭据、重放、目标变化只产生零个或一个正确任务。
5. 精确目标测试覆盖 Formula 同版本内容变化及确认/安装之间的源更新；不能只在安装完成后才发现装错版本。
6. 只有 TokenLive 及明确允许的包管理操作；浏览器输入不能成为命令/URL/路径注入。
7. 主服务停止/启动、浏览器关闭、进程异常退出不丢失任务状态，不制造第二个执行器。
8. 网络失败、包校验失败、安装失败、重启失败、超时、状态文件损坏分别有安全终态或 needs_attention。
9. 错误版本、无关 HTTP 服务、未完成初始化和仅端口可连均不能通过健康核验。
10. 旧 Admin 无可选宿主能力时不暴露执行；专业版保持原有行为；Standalone 按真实兼容依赖构建。
11. 新增权限菜单、状态文案和确认警告有中英文及浏览器测试；修改前端须 Prettier。
12. 常规测试用临时目录、替身 Homebrew/服务管理命令和受控进程，不安装用户的软件，不操作真实服务或业务数据。

真实 Homebrew 与系统任务托管的端到端验证必须在独立测试环境中进行，并单独取得执行安装/重启的授权。模拟命令测试通过不构成真实自升级已验证；当前对设计的确认不是让代理现在升级用户机器。

## 9. 实施前必须验证的技术门槛

正式分解实施任务前，应完成只读研究或可销毁的隔离验证；这些是实现者的工作，不让用户替代技术调查：

1. **目标固定**：当前支持的 Homebrew 接口能否消费确认时固定的 Formula/产物而不被自动更新或并发 tap 变化替换，且维持正常包管理身份。
2. **生命周期**：同用户一次性系统任务能否在对应 brew 服务重启后继续执行，执行器文件不受旧包清理影响，任务结束能正确清理自身注册。
3. **服务归属**：能否可靠关联当前进程、实际安装前缀、brew 服务用户与管理域，排除仅同名或其他安装实例。
4. **副作用及诊断**：固定调用在所支持 Homebrew 版本中会不会隐式升级/清理其他软件、交互请求信任或锁住未决安装；是否有可验证的有界退出与诊断路径。

这些门槛当前尚未验证完成。若任一门槛无法满足，应提交事实和最小方案调整供用户确认，不以“尽力执行”悄悄放宽精确目标、不提权或失败恢复规则。

## 10. 已核对的代码与资料

- Admin：`adminapp/app.go` 的可选宿主配置入口；`internal/mods/systemversion` 的版本能力/授权；现有 UpdateCheck 关闭语义。
- Standalone：`cmd/tokenlive/main.go` 的安装标记与信号生命周期；`internal/assemble/assemble.go` 的服务组装与健康入口。
- Standalone Homebrew Formula：用户服务运行 `opt_bin/tokenlive`，配置/数据位于版本包之外；执行器尚不存在。
- 本机 Homebrew 自带源码与手册：`/opt/homebrew/Library/Homebrew/cmd/upgrade.rb`、`services/system.rb`、`services/cli.rb`、`/opt/homebrew/share/man/man1/brew.1`。只读检查提示升级副作用、锁和服务管理域必须专项验证。

官方在线手册检索本轮未返回可用内容；本机源码阅读仅说明本机实现，不能代表所有 Homebrew 版本。没有运行安装、升级、服务重启或发布命令，没有修改业务源码。

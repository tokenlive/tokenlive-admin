# 服务端更新检查独立于业务运行

为兼顾默认发现新版本与离线部署，采用默认启用、可关闭的服务端定时更新检查，并提供手动检查入口。
更新检查仅获取公开发布信息，不上传业务数据。
检查失败不影响正常业务使用，界面显示“暂时无法检查”，不能据此标记“已是最新版”。

## 更新提醒与交互权限

普通登录用户仍可查看当前版本；更新提醒、更新详情、升级指引和手动检查仅对更新管理员开放。
更新管理员在侧栏版本旁看到“有更新”标记，点击“关于”查看详情、升级指引或手动检查。
更新提醒不主动弹窗打断操作。

## 可委派的版本更新管理权限

Root 默认拥有“版本更新管理”权限，其他用户可通过角色授权获得该权限。
后端负责校验权限，前端依据后端的权限结果显示提醒和操作入口，不通过用户名判断管理员身份。

## 更新信息来源

单机版直接读取 Homebrew 安装源中的已发布版本，专业版分别读取 Admin、Gateway 各自的正式 Release。
本期不增加统一的公开 JSON 发布清单：虽然统一清单可以统一数据格式，但还需要额外维护生成、同步和发布环节，因此优先复用既有发布渠道。

## 联网关闭与历史结果

关闭联网更新检查后，定时检查和手动外部检查均停止，本地版本展示和部署内部的 Gateway 版本上报不受影响。
检查失败时可以保留上次结果，但必须明确标记已过期，不能作为本次检查成功的结论。
检查周期、冷却、超时和节点上报时效统一定义在[完整设计](../superpowers/specs/2026-09-11-edition-versions-update-notifications-design.md)中。

# 供应商健康指标分别表达有效性与统计范围

Status: accepted

## Context

Gateway 的 Prometheus provider 维度记录最终请求，而 Redis 状态记录每次上游尝试。故障转移后成功的请求无法用最终供应商请求计数还原前一供应商的失败。旧返回结构还用零值表达所有缺失与错误，且一次源探测决定整组指标，导致调用数、请求性能和当前库存互相影响。

## Decision

- 延续 ADR-0008、0009：上游调用数及成功率仅使用 Redis／内存中的尝试记录，分子分母从同一来源、同一窗口、同一标识派生。供应商详情流量图复用相同分钟观测；不使用当前 Prometheus Request 计数代替。
- `Reader.Read` 的供应商行返回独立 `MetricObservation`：可空值、状态、来源、统计范围、窗口、覆盖范围和稳定原因。真实零值与无样本分开；零调用无法推导成功率。单项失败不清空整行，未知值排在已知值之后。
- 性能保留现有含义：Prometheus 为最终供应商归属的请求；带 Attempts 的内存上报为成功供应商归属的请求。旧版不带 Attempts 的性能仍保留，明确标记为归属请求样本，不能用于补齐上游调用数；混合上报时已知尝试可作为部分计数保留。耗时包括请求起点到完成的过程，并非每次上游尝试的独立耗时。
- code 按键是否存在优先于 name，每个源、每个整窗口只选一次，零和无效样本均不触发跨标识拼接。名称只用于兼容，并显式暴露其身份。
- Redis 只读取实际两小时保留窗口的交集；过期窗口使用内存可覆盖区间，Redis 失败时内存降级明确为部分数据。所有 Redis 候选键都不存在时返回无样本，不把沉默当作真实零。内存值仅代表本实例观测。
- 性能整组选用 Prometheus 或内存，但每个查询独立表达失败、不支持或无样本。无法验证 Prometheus 历史覆盖时，已读到的指标保留为部分数据，不声称覆盖完整。
- 端点数来自当前配置，熔断数来自当前运行状态；二者携带当前观测时刻，独立于历史请求窗口。

## Consequences

HTTP、页面卡片和顶部成功率统一解释有效性。调用方无需根据零值、数据源优先级或兄弟指标推断是否有数据。供应商旧扁平字段已移除，仓库内消费者同步迁移，不保留兼容响应。

不补造分位数、不解析错误文案推断 429／401、不修改 Gateway 埋点，也不在本轮重构详情页的查询编排。首页 ClickHouse 使用趋势仍遵循 ADR-0010：未启用时隐藏整卡。

# 复合模型实现状态与联调入口

日期：2026-11-11。配套设计：`../specs/2026-11-11-composite-model-routing-design.md`。

## 已落入 Admin 仓库

- 模型详情中的“选模配置”支持主备、规则、旧难度三种编辑方式。新配置默认主备，允许一个主模型，无需裁决器。
- 规则支持启停、顺序调整、AND/OR、结构化标签与白名单业务 Header，第一条命中即停止，无命中使用默认模型。
- `POST /api/v1/models/:id/route-preview` 可预演保存配置或草稿；复用 `pkg/compositerouting` 的纯计划函数，无 LLM、配额和业务写入。
- 预演依照当前管理员的模型读权限展示目标，不等同于真实 API Key 调用权限检查。不可见目标与不存在目标返回相同状态。
- 格式 2 的保存、校验、深拷贝、稳定 ID 依赖、运行态编码转换及依赖导出；旧格式继续按难度路由处理。
- 新配置沿用已有 `PUT /models/:id/smart-routing`，保存不启用；过期版本整体拒绝。未新增聚合配置事务接口。
- 前后端均检查服务端 `Gateway.CompositeRoutingV2`，默认 false；停用草稿可以保存/预演，但启用、启用状态的配置变更和运行态编译不能绕过该开关。
- 菜单权限配置增加预演资源。已有环境需要按项目正常菜单同步流程导入更新后的菜单权限。

## Gateway 补丁

用户已在同级 Gateway 仓库应用 `../patches/composite-routing-gateway-v2.patch`。已核对实际文件并在该仓库运行定向测试，未部署服务。原有 `CONTEXT.md` 改动未触碰。

补丁包含：

- 格式 2 配置解析、校验、克隆、依赖枚举；未知格式拒绝。
- 与 Admin 字节一致的 `pkg/compositerouting` 源码及相同测试。当前为同步源快照，后续修改需同时更新两侧，不能分别手写不同的预演算法；独立共享模块的发布留待后续整理。
- 主备/规则执行分支，不经过裁决；备用链读取复合模型当次有效 Invocation 策略，子模型仍禁用递归跨模型 fallback。
- 文本 Chat Completions 流式透传，以及按实际 response writer 提交状态停止模型切换。
- 全请求最多调用 3 个模型、6 次上游尝试；重试和 hedging 通过 context 共享原子尝试计数。默认总期限 60 秒，可由复合模型有效 RetryPolicy 的 TotalTimeout 覆盖。
- 跨模型切换继续沿用当前 `CanFallbackModel` 的“无可用端点”与亲和性约束，不自动扩大成任意 429/5xx 的重放。
- 规则命中、模式、实际执行目标记录；旧难度和普通模型的已有行为保持。

补丁已应用，不要重复执行 `git apply`。Gateway 与 Admin 的纯选模源码已逐字节核对一致。

## 复核修复（2026-11-11）

本轮修复针对代码复核发现的五项问题，未扩展聚合保存、发布代次和效果页面的交付范围。

Admin 原工作目录已更新：

- 新模式保存、启用和运行态编译检查明确的上下文、输出上限及能力承诺；至少一个有效选模目标的声明须覆盖入口承诺，停用规则不能用于证明。当前可声明的扩展能力仅为 `stream`。
- 基本信息编辑同样检查能力承诺，不能通过省略选模配置绕过校验。旧难度模式保持原有行为。
